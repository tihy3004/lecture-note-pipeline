# Lecture Note Pipeline

Convert raw lecture transcripts into structured course notes, and keep a set of
small knowledge libraries that improve accuracy on every subsequent run.

## Core idea

Raw ASR transcripts are long, unstructured, and full of recognizable errors.
Notes generated from them lose a lot — especially **exam, grading, and
assignment information**, which is the most valuable part to a student and the
first thing a summarizer drops.

This skill fixes that with a three-part loop:

1. **Process** transcripts from an inbox into structured notes.
2. **Audit** any existing note against its source transcript rather than
   creating a duplicate.
3. **Grow two libraries** from what each run discovers, so the next run is more
   accurate. This feedback step is what makes the pipeline worth using twice.

## Directory layout

Adapt these paths to the target vault; the defaults below assume a course-notes
vault.

```
<vault>/
├── <Course Name>/
│   ├── 第N讲 <Lecture Title>.md        # the note
│   └── <Course Name> MOC.md            # per-course index (Map of Content)
├── 录音文件转文字版/                     # transcript inbox
│   ├── <dropped .txt>                  # PENDING  = loose in this root
│   └── YYYY-MM-DD/
│       └── 第N讲 <Title> 原始转写.txt     # ARCHIVED = inside a date folder
└── copilot/copilot-custom-prompts/
    ├── ASR术语纠错库.md                  # library 1: correction table
    └── 知识关联网络提示词.md              # library 2: controlled vocabulary
```

### Pending vs. archived — decide by **location**, not filename

- A `.txt` **loose in the inbox root** → pending, needs processing.
- A `.txt` **inside a `YYYY-MM-DD/` folder** → already processed, skip it.

This makes re-running the pipeline idempotent: the user never has to mark
anything, and repeating the trigger will not regenerate notes.

## Workflow

### 1. Read the transcript directly

Read the `.txt` from disk. **Never ask the user to paste the transcript text** —
removing copy-paste is the single biggest speed win in this pipeline.
Transcripts are often 20k–30k characters; read in chunks if needed.

### 2. Identify course and lecture number

Determine from the content which course and which lecture it is. The folder name
is **not** authoritative — the user may drop the file anywhere.

**If you cannot identify it confidently, ask the user.** Do not guess.

### 3. Determine the date

Prefer, in order:

1. A date the instructor states in the transcript.
2. The `日期` field of the corresponding note.
3. Ask the user.

**Do not infer from file timestamps** — export time is not class time.

### 4. Check for an existing note — audit instead of duplicating

Before writing, check whether a note for this lecture already exists.

- **No existing note** → generate a new one from the template.
- **Existing note** → **do not create a duplicate.** Switch to audit mode:
  - Fill in knowledge points present in the transcript but missing from the note.
  - **Fill in exam / grading / assignment information** (see Quality rules).
  - Correct factual errors and invert any claim that contradicts the instructor.
  - Mark content with no transcript basis as `[AI 补充]` / `[AI supplement]`.
  - **Do not rewrite the user's existing prose.** Add and correct only.

This matters because transcripts are frequently handed over *after* notes were
generated by some other tool. Generating again would silently double the vault.

### 5. Write the note

Use the template in `references/note-template.md`. Save as
`<Course>/第N讲 <Title>.md`, where the filename matches the internal
`# 第N讲 <Title>` heading **character for character**.

Frontmatter uses whatever key convention the vault already follows — check an
existing note first, and never mix conventions within one vault.

### 6. Link concepts inline

Wrap concept terms in `[[ ]]` in place, without altering the surrounding
wording. Use canonical names from the controlled vocabulary (library 2).

### 7. Archive the transcript

Rename to `<Lecture Title> 原始转写.txt` (or `<Title> transcript.txt`), move it
into the `YYYY-MM-DD/` folder for its class date, and link it from the note's
appendix.

Use a **plain link `[[...]]`, not an embed `![[...]]`** — embedding a 25k
character transcript makes the note unreadable.

### 8. Write back to both libraries

This step is **mandatory and must not be skipped**, or the pipeline never gets
more accurate. See `references/libraries.md`.

1. Append newly found ASR errors to the correction library. Add only; never
   edit or delete existing rows.
2. Register newly used concept names in the controlled vocabulary.
3. If an existing note uses a non-canonical concept name, fix it there too.

### 9. Update indexes

If the vault indexes notes automatically (e.g. an Obsidian Base filtered by
folder or property), the new note appears on its own. Only update index pages
manually when a **new course** or a **new index entry** is genuinely required.

## Quality rules

These encode the failure modes this pipeline exists to prevent.

### Exam, grading, and assignment information is mandatory

Always emit dedicated sections for exam scope and for assignments/requirements.
Actively hunt the transcript for: exam format, question types, point values,
grade weighting, pass thresholds, assignment submission rules, deadlines,
attendance rules, textbook and reference editions, and any stated policy.

A note that captures every concept but loses the grading scheme has failed.

### Numerals must be verified against the source

ASR routinely corrupts numbers — `104.365` becomes `164.31`, `3.167` becomes
`3.157`, `220V` becomes `20V`. Any number that will be used in a calculation
must be traced back to the transcript text before it is written down.

### Never silently invent content

Anything you supply that the transcript does not support must be labeled
`[AI 补充]` (or the vault's equivalent marker). This applies especially to:

- Worked answers the instructor read out but never solved.
- Formulaic definitions the instructor gestured at rather than stated.
- "Corrections" of the instructor that are really the model's own knowledge.

### Watch for inverted claims

A summarizer can record a policy **backwards**. Verify any statement about
rules, permissions, or instructor stance against the transcript — an inverted
AI-use policy or attendance rule is worse than a missing one.

### Preserve the user's prose

When auditing, do not reword existing sentences. Add, correct, and annotate.

## Batch processing

When several transcripts are pending, **process them in parallel** (subagents or
a workflow) rather than serially. Keep each transcript in its own worker so the
workers do not contend over the same note.

Have each worker **report back** the new ASR errors, new concept names, and a
list of the exam/assignment information it captured — the parent run needs those
to write back to the libraries without re-reading every transcript.
